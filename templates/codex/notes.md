# Codex CLI + hkb

Generated by `hkb init --harness codex` — do not edit; re-running init overwrites this file.
Full write-up: <https://github.com/emyann/harness-kanban-board/blob/main/docs/harnesses.md>

## What is here

- `hooks.json` — a `Stop` hook that runs `{{command}}`. When a worker tries to end its turn while its
  task is still `running` on the board, the hook answers `{"decision":"block"}` with the terminal verb it
  owes (twice at most, then it lets go and the dispatcher records a `protocol_violation`).
  The hook is inert in your own sessions: `hkb hook stop` exits 0 immediately unless `KB_TASK` is set.

The dispatcher launches a Codex worker as

```
codex exec -C <worktree> --sandbox workspace-write \
  --output-schema .agents/skills/kanban/schema/terminal.json "<task context>"
```

in a worktree it created for that attempt (`.claude/worktrees/kb-<n>-<k>`, branch `kb-<n>-<k>`).

## One-time trust — nothing below runs until you do this

Codex does not execute hooks from a project it has not been trusted with, and `--sandbox workspace-write`
does not by itself make a directory trusted. Once per machine and repo, either:

1. Run `codex` in this repository and use **`/hooks`** to review what `.codex/hooks.json` declares and
   trust it. This is also the quickest way to confirm Codex sees the file at all.
2. Or mark the project trusted in `~/.codex/config.toml`:

```toml
[projects."{{root}}"]
trust_level = "trusted"
```

## Config notes for `~/.codex/config.toml`

Codex reads its configuration from `$CODEX_HOME` (`~/.codex` by default), not from this directory, so these
are settings to add there — hkb does not write them for you.

```toml
[sandbox_workspace_write]
# `gh`, `git push` and the lock-ref heartbeat all need the network
network_access = true
# a worktree's git metadata lives in the main repo, outside the worker's cwd
writable_roots = ["{{gitdir}}"]
```

Without `network_access` a worker can edit files but cannot push a branch, open a PR or heartbeat, and the
dispatcher will reclaim the attempt as stale. Without the `.git` writable root, `git commit` inside the
worktree can be denied by the sandbox — add it if commits fail with a sandbox error.

No `[mcp_servers]` entry is generated: hkb workers call the `hkb` CLI directly, so there is nothing to
connect. To drive the board through tools instead, run `hkb init --mcp` — it prints an `mcp_servers.kanban`
snippet for `~/.codex/config.toml`. Either way that table belongs in the user config, never here.

## The protocol

Codex reads `AGENTS.md`, and `hkb init` keeps the kanban section of that file up to date — that plus
`hkb show $KB_TASK --json` is everything a worker needs. The full protocol lives in
`.agents/skills/kanban/SKILL.md`.
